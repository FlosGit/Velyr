Email field missing required validation — plus a duplicate class attribute

The contact form lacks inline validation and only shows errors after submission, forcing users to submit blind and then hunt for what went wrong.

Agent reasoning

The contact-form.liquid file shows error handling only after form submission (form.errors block) with no client-side validation or real-time feedback. The email field has aria-invalid and aria-describedby attributes that only activate post-submission. Users must click ‘Send’, wait for server response, then read error messages and scroll to find the problem field. This creates unnecessary friction in a conversion-critical form.
